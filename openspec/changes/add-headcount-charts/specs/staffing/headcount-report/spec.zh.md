> 结构关键字（`ADDED Requirements` 段、Traces 行、GIVEN / WHEN / THEN / AND 标记）以及角色、

范围：headcount 报表 —— 针对启用人员池的两张柱状图（按角色、按等级），一次读取，渲染在既有的人员池页面内。该报表不持有任何状态：每个数字都由 REQ-001 已经保存的行派生。

## ADDED Requirements

### Requirement: 报表只描述启用人员池

系统应只统计 `active` 为 true 的人员，并应通过一次不写入任何数据、只读的请求，返回这些人员的人数、按角色的分组以及按职级的分组。总数应等于角色人数之和，也应等于等级人数之和，因为两种分组描述的是同一个池子。已停用的人员不得出现在任一分组与任一总数中。

**Traces:** proposal 步骤 1、步骤 2 与关键规则 "One pool, two axes"、"Active only"；REQ-002 §3、§5；S1、S2。

#### Scenario: 两张图描述同一个池

- **GIVEN** 一个由 113 名启用人员组成、分布在四个角色与三个职级上的池
- **WHEN** 读取该报表
- **THEN** 总数为 113，角色人数之和为 113，等级人数之和为 113
- **AND** 两张图展示同一个总数

#### Scenario: 已停用人员不进任何一张图

- **GIVEN** 一个总数为 113 的池
- **WHEN** 再导入一名 `active` 为 false 的人员
- **THEN** 总数仍为 113，且没有任何柱子变化

### Requirement: 轴上的每个分类都保留自己的柱子，顺序来自模型

系统应为轴上的每个分类返回一根柱：目录仍提供的每个角色（`active`）、所有仍持有启用人员的角色，以及四个职级带。人数为 0 的分类应保留一根 0 高的柱，而不得因为为空而被省略。角色柱应按角色在目录中的次序排列，等级柱按 `Junior` < `Senior` < `Lead` < `Principal` 的带序排列；两种顺序都不按人数大小。柱子应以库中存储的角色名命名，因此被停用的角色在其仍有启用人员时保留自己的柱；已停用且无人的角色应离开该轴，因为目录已不再提供它。

**Traces:** proposal 步骤 4 与关键规则 "Empty categories keep their place"、"Order comes from the model"、"A deactivated role still counts its people"；REQ-002 §3、§5、B-3、B-3b、B-4、B-5、B-6、B-11；S5、S6、S7、S11。

#### Scenario: 没有人的分类保留自己的柱子

- **GIVEN** 没有启用人员持有 `QA` 角色，也没有人处于 `Principal`
- **WHEN** 读取该报表
- **THEN** 角色分组中有一根 `QA` 柱，等级分组中有一根 `Principal` 柱
- **AND** 两根都画在 0 高度，读作 `0` 与占比 `0.0`

#### Scenario: 角色柱按目录顺序

- **GIVEN** 启用人数为 PM 40、BA 25、DEV 34，且 `QA` 与 `UX` 在轴上但无人
- **WHEN** 读取该报表
- **THEN** 角色分组按目录顺序排列为 PM、BA、DEV、QA、UX
- **AND** 两根 0 值柱都在场，且顺序不按人数

#### Scenario: 等级柱按带序

- **GIVEN** 启用人数为 Senior 42、Junior 38、Lead 28，且 `Principal` 无人
- **WHEN** 读取该报表
- **THEN** 等级分组排列为 Junior、Senior、Lead、Principal
- **AND** 人数最多的那一项不在最前，且 0 值的那一带在最后而不是缺失

#### Scenario: 停用的角色仍统计其在职人员

- **GIVEN** 一个已被协调员停用的角色，仍有三名启用人员持有它
- **WHEN** 读取该报表
- **THEN** 该角色以库中存储的名字保留一根柱，且总数不变
- **AND** 另一个已停用且无人的角色不在该轴上

### Requirement: 每根柱带人数与占总数的比例

每根柱应带原始人数，以及占总数的百分比（一位小数、四舍五入），因此 113 人中的 40 人读作 `35.4`。持有整个池子的分类应读作 `100.0`。不得为了让占比精确合计为 100.0 而调整占比：合计为 99.9 或 100.1 的残差应被接受，人数应保持精确。

**Traces:** proposal 步骤 3 与关键规则 "Shares are rounded once, and never corrected"；REQ-002 §5、B-8、B-9、B-10；S3、S4。

#### Scenario: 柱子带人数与占比

- **GIVEN** 113 人的池中有 40 名启用人员持有 `PM` 角色
- **WHEN** 读取该报表
- **THEN** 该柱返回人数 40 与占比 35.4

#### Scenario: 占比四舍五入到一位小数

- **GIVEN** 分别为三人（其中一人、两人在同一角色）与八人（其中一人）的池
- **WHEN** 分别读取该报表
- **THEN** 占比分别读作 33.3、66.7 与 12.5

### Requirement: 两张图是人员池页面中的一个区块

系统应把两张图各自连同其总数，作为既有人员池页面中的一个区块渲染，位于人员表上方。每根柱应按人数成比例绘制，并以文字带出人数与占比。不得为该报表引入独立屏幕或额外路由。人员表应继续列出所有已导入的人员（含已停用），使同一页同时呈现池子的行与启用池的形态。

**Traces:** proposal 步骤 5 与关键规则 "Two numbers on one screen, two meanings"；REQ-002 §3、§6、B-14；S8、S12。

#### Scenario: 两张图都在人员池页面上

- **GIVEN** 一名已登录的协调员
- **WHEN** 打开 `/people`
- **THEN** 两张图连同各自总数出现在人员表上方
- **AND** 不存在任何为报表可达的其他屏幕

#### Scenario: 表格与图表刻意不同

- **GIVEN** 一个池中除启用人员外还有一名已停用人员
- **WHEN** 协调员读取该页面
- **THEN** 人员表列出该停用人员
- **AND** 总数与每根柱只统计启用人员

### Requirement: 报表仅属于协调员

系统应把该报表返回给资源协调员，对项目经理应以 `403` 拒绝且不返回任何数字。人员池页面应只对协调员渲染图表区块：项目经理打开该页面时不得看到图表区块、占位或拒绝文案，系统也不得在该页面向其返回报表。

**Traces:** proposal 关键规则 "The report is the coordinator's, and a lead sees no trace of it"；REQ-002 §2、§6、B-12、B-13；S9。

#### Scenario: 项目经理看不到报表

- **GIVEN** 一个仅持有项目经理角色的用户
- **WHEN** 打开 `/people`，并另外直接请求该报表
- **THEN** 页面不绘制图表区块，也不请求报表
- **AND** 直接请求返回 `403`

### Requirement: 空的池被陈述，而不是被画出来

当没有任何启用人员时，系统应返回总数 `0` 与两个每个计数都为 `0` 的分组；页面应说明池中无启用人员，而不是绘制柱子或占比——该空态应替换两张图（包括其中的 0 值柱），因为最高柱为 0 的图没有可绘制的刻度。该情形下报表不得用总数做除法。

**Traces:** proposal 步骤 2、步骤 5；REQ-002 §6、B-7；S10。

#### Scenario: 空的池会说明

- **GIVEN** 一个所有人员都已停用的池，或一个根本没有任何人员的池
- **WHEN** 协调员读取人员池页面
- **THEN** 两个图表区都说明没有启用人员，且总数为 0
- **AND** 不出现柱子、占比，也不发生除以零
